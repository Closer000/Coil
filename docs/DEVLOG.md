# 开发日志

## 阶段0：起步

### 11.06~11.08

绘制出游戏窗口，确定“黑底白字”的配色方案。绘制了单个方块作为蛇头，方便移动逻辑的测试。
先选择了移动速度与帧率挂钩的移动逻辑，这样代码简单易写，但是当帧率受到影响时蛇的速度会发生突变，
影响游戏体验。所以将其改为“使用GetFrameTime()函数获取每帧耗时然后累加，达到预设步间隔后移动一格”
的逻辑，这样的写法让蛇的移动稳定下来，同时也引入了“网格”坐标与像素坐标的转换。
按格移动的贪吃蛇才是经典贪吃蛇的表现。

方向输入方面，一开始采用“每按下一个键就在相应的方向坐标上增加或减少一格”的方式。
但是同时按下两个相邻方向键会导致贪吃蛇在对角线方向上移动；同时按下两个相反的方向键时，
贪吃蛇会立马调头，如果后续加入身体，就会直接触发“撞到身体”的死亡判定，是严重的BUG.
所以把方向的输入改为按下一个方向键时，控制两个方向的变化，比如：按下“A”就让蛇头的坐标在X轴上减1（Δx = -1），在Y轴上
保持不变（Δy = 0），这样在向左移动的同一帧内就不能向其他方向移动，“对角线移动”的问题就解决了。

对于同时按下两个相反的方向键时直接调头的问题，加入了“反向保护”的判定：如果这一帧蛇头将移动到的位置
是上一帧蛇头所在的位置，那么本次方向输入不生效。

加入了“Game Over”页面（撞墙触发，因为此时还没有做蛇身）

加入了蛇身，用两个数组分别储存蛇身每一节的X，Y坐标。采取环形缓冲的方法，储存最旧的那一节身体的坐标作为基准，有效的下一位置的坐标会被存到数组中与最旧身体间隔
“身体长度-1”个元素的位置，如果判定到“吃了食物”则保留最旧的一节身体同时身体长度加1；如果没有吃到，则将新位置的蛇身作为“最旧身体”同时身体长度不变。
然后绘制蛇身的时候从“最旧身体”开始，这样就把不需要的那一节“丢掉”了。注意下标要取模，防止数组溢出。

食物随机生成，当新食物的坐标与蛇身重合时重新随机生成新的坐标，直到不与蛇身重合为止。
同时记录重新生成的次数，该次数过高说明出现BUG或蛇身几乎占满盘面，此时继续生成容易出现“卡死”
的情况，所以设置上限100，达到该上限就放弃继续重掷并返回失败；此时食物位置可能仍与蛇身重合，需要后续处理。

设计状态机，分两级菜单：

- `game`：-1 失败 / 0 主菜单 / 1 游戏中 / 2 胜利
- `menu`：0 标题画面 / 1 难度选择 / 2 按任意键开始

做了“文字按钮”函数，绘制纯文字的无边框按钮鼠标悬停时变为黄色。

加入记分系统，每吃到一个食物加一分。达到目标分数即可胜利，难度与目标分数挂钩。

绘制了图标，使用 DeepSeek-v4.1-Flash 模型生成音效素材，暂未加入游戏中。

## 阶段4：模块化

### 11.12~11.14

先从 `coil.c` 中把由各通用参数组成的结构体 `Game` 抽出，放入 `game.h`，后将食物生成函数抽出放入
food.c，将文本按钮绘制函数放入textbutton.c，将蛇身绘制、食物绘制、分数绘制三部分放到render.c中，
将重开初始化函数放入state.c中。

这些模块化的操作都是为了项目的持续进行以及减少BUG检修时的困难，使结构更加清晰。

为了让模块的命名更准确，将 `state.c` 拆成 `restart.c` 和 `rules.c`：`restart.c` 只放初始化函数，`rules.c` 存放帧耗时 dt 的钳制、蛇身移动和自撞检测。

接下来，将方向输入部分放进input.c，将初始菜单，失败画面，胜利画面放入menus.c。
最后在src/下又划分了 Code / Head ，分别存放.c和.h

至此，模块化结束。这些模块中的函数参数均采用结构指针，直接修改结构“Game”中
的参数，且都是不返回任何值的函数，这样避免了主函数中调用不同模块时
所需参数不同的麻烦，虽然有更改与所调用的模块无关的数据的可能性，但是只要不把相应函数中的参数
写错就基本不会有这种情况发生。

## 阶段5：其它问题修复

### 11.15~11.16

修复了桌面图标模糊的问题：原 ICO 只有 16×16 一帧，Windows 放大后变糊；改为多尺寸 ICO（256/128/64/48/32/16）

将 preset 里的绝对路径改为环境变量，并将变量名定为 `COIL_VCPKG_ROOT`，防止 VS 覆盖工具链。这两处改动保证了项目的可移植性。

将源码注释的编码从 GBK 统一为 UTF-8 带 BOM，并给 MSVC 加上 `/utf-8` 编译选项，避免换系统或换编辑器后中文注释乱码。
